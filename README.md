# OpenAI Codex Plugin for DeepSeek Harness

`dsh-openai-codex-auth` lets DeepSeek Harness (DSH) use OpenAI Codex
subscriptions. Sign in with one or more OpenAI accounts, compare their usage,
activate the account DSH should use, and run the `openai-codex` model provider
without copying tokens into the web interface.

It also:

- Adds a working `image_gen` tool that displays images in the conversation and
  can save a PNG to a chosen path in the current DSH workspace.
- Fixes web search when using Codex in DSH by routing `web_search` through
  OpenAI instead of making a separate DeepSeek API request.
- Supports device-code sign-in on SSH, containers, and other headless systems.

This is an independent community plugin. It is not made or endorsed by OpenAI
or DeepSeek.

## Install the DeepSeek Harness Codex plugin

Add it to your DSH Web profile:

```sh
dsh plugin --profile web add github:Eve-146T/deepseek-harness-openai-codex-auth
```

## Sign in with OpenAI

Restart DSH Web:

```sh
dsh --profile web
```

Then:

1. Open **Settings → OpenAI Codex**.
2. Select **Sign in** and finish signing in.
3. Open **Settings → Model Providers** and choose `openai-codex`.

That is all you need for a normal local installation.

To pool usage across subscriptions, select **Add another account**. Each
account keeps its own usage display. Use **Activate account** to choose which
credential powers Codex models, web search, and image generation; signing out
of one account leaves the others connected.

The same page includes three local display settings. **Hide useless models**
keeps the model picker focused on the GPT-5.6 series and GPT-5.3 Spark, **Email
privacy** masks the part before `@`, and **Show generated images in threads**
can hide generated-image cards without disabling image generation or file
saving.

### Headless or SSH sign-in

Open **Settings → OpenAI Codex**, select **Use device code**, then open the
displayed OpenAI page and enter the code.

Without DSH Web, start the same flow from the machine running DSH:

```sh
curl http://127.0.0.1:1456/start-device
```

Open the returned `url`, enter `userCode`, and leave DSH running while it
finishes. Device-code login may first need to be enabled in your ChatGPT
security or workspace settings. See OpenAI's
[headless login documentation](https://developers.openai.com/codex/auth#login-on-headless-devices).

## Generate images

The plugin registers `image_gen` automatically. Ask the selected model to
create an image, or call the tool with a prompt and optional size, quality, and
`output_path`. The path must end in `.png` and stay inside the current DSH
session workspace. Parent directories are created, and existing files are not
overwritten. Generated bytes are also saved through DSH's attachment storage,
so session logs contain a durable attachment reference rather than base64 data.

Supported sizes are `1024x1024`, `1536x1024`, and `1024x1536`; quality can
be `low`, `medium`, or `high`. The request uses OpenAI's hosted
[`image_generation` Responses tool](https://developers.openai.com/api/docs/guides/tools-image-generation).

## Security

- Access and refresh tokens stay on the machine running DSH.
- The browser settings page never receives the tokens.
- Login uses OAuth PKCE and validates a random callback state.
- Device-code sign-in avoids a browser callback on the DSH host.
- The multi-account credential file uses owner-only permissions and atomic updates.
- The callback and status services bind only to `127.0.0.1`.

The plugin uses OpenAI's Codex OAuth flow and usage endpoint. Those interfaces
are not documented as a public third-party integration, so they may change.

## Troubleshooting

- **The sign-in window does not open:** allow pop-ups for DSH Web and try again.
- **The plugin service is unreachable:** restart the `web` profile and open DSH
  Web on the same machine.
- **No usage limit appears:** OpenAI may temporarily return no displayable
  weekly window even while the account remains connected; the plugin retries
  automatically.
- **An image path already exists:** `image_gen` intentionally refuses to
  overwrite it. Choose another output path or remove the old file first.

## Optional credential path

Credentials normally live at `$DSH_HOME/openai-codex-auth.json`. To use another
location:

```yaml
- insert:
    - id: openai-codex-auth
      name: dsh-openai-codex-auth
      config:
        path: /secure/path/openai-codex-auth.json
```
